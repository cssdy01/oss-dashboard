================================================================================
OSS DASHBOARD PLATFORM - AI AGENT BUILD PROMPTS
================================================================================

HOW TO USE THIS FILE
--------------------
1. This file contains a sequence of prompts, one per task. Copy ONE prompt at
   a time into your coding agent, in order, and let it finish before moving
   to the next prompt.
2. Make sure the agent has read access to
   "OSS_Dashboard_Product_Development_Guide.md" (place it in the repo root or
   attach it to the agent's context) BEFORE you paste Prompt 0. Every later
   prompt references this guide by section number instead of repeating it.
3. This environment has no Java runtime, no Node runtime, no Docker, no
   Kubernetes and no database engine available. Every prompt therefore asks
   the agent to WRITE CODE, CONFIGURATION AND TESTS ONLY. The agent must
   never attempt to compile, run, build, containerize or execute anything.
4. Every prompt ends with a "Validate" instruction. This only means the
   agent must review its own output against the referenced requirements and
   state clearly whether each requirement is fulfilled or not fulfilled
   (Yes/No + short reason). It does NOT mean running any command.
5. After all prompts are complete, copy the finished codebase out of this
   environment and build/run/test it on a normal machine with Java, Node,
   Docker etc.

PROMPT 1.1 - tmf-core HTTP transport module
--------------------------------------------------------------------------------
Reference: section 7.4 (Connector design) and section 13 backend structure
(tmf/tmf-core/http/).

Implement the tmf-core Maven module with the following Java classes inside
tmf/tmf-core/http/:
- TmfHttpExecutor: shared HTTP client wrapper used by every TMF module
  gateway. Must support configurable timeouts, base URL resolution per
  connection, and pluggable interceptors.
- AuthenticationInterceptor: resolves and applies the correct auth scheme
  (API key, OAuth2 client credentials, basic auth) per connection, reading
  credentials only from a CredentialResolver interface (do not implement
  storage yet, just the interface and interceptor contract).
- CorrelationInterceptor: propagates a correlation ID header on every
  outbound request, generating one if absent.
- PaginationExtractor: interface + default implementation to extract next
  page cursors/links per TMF pagination conventions.
- ErrorDecoder: translates TMF error payloads into a typed TmfApiException
  hierarchy (NotFound, Validation, Unauthorized, Forbidden, RateLimited,
  ServerError).
- RequestContext: carries correlation ID, connection ID, requesting user
  authorities, and environment classification through the call.

Also create tmf/tmf-core/error/, tmf/tmf-core/pagination/,
tmf/tmf-core/filtering/, tmf/tmf-core/validation/, tmf/tmf-core/logging/,
tmf/tmf-core/correlation/, tmf/tmf-core/security/ and
tmf/tmf-core/resilience/ with the supporting classes each package name
implies (filtering DSL for TMF query params, validation base classes,
structured logging helpers, correlation ID utilities, security context
helpers, and resilience primitives: timeout, circuit breaker, bulkhead,
retry-safety guard for write operations per section 17.4).

Write unit tests (JUnit 5) for every class above, covering both success and
failure paths. Do not run the tests.
